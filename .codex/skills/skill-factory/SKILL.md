# 项目技能提炼

先读 `.codex/skills/README.md`，再找对应的事实源（根 AGENTS.md、`internal/aiprompts/`、`internal/develop/` 或执行计划）。

## 何时值得提炼

同时满足以下四条：

1. 工作流重复出现，且每次都要重新解释长规则
2. 有稳定的入口、边界、输出和验证方式
3. 仓库事实源已经存在，或本轮会同时补齐
4. skill 只做路由和执行判断，不替代事实源

不要把一次性修复、个人偏好、未确认的计划或纯背景介绍做成 skill。

## 提炼流程

1. 收集两三次真实请求和执行差异，写出共同目标。
2. 找唯一事实源。
3. 定义触发条件和不触发条件，避免 skill 变成万能入口。
4. 只写非显然的工作流：先读什么、如何判定 owner、何时停止、如何验证、如何汇报。
5. 稳定规则放进 SKILL.md；长背景、模板和清单另放 `references/`，按需读取。
6. 命名：`name` 与目录一致，用短的领域词，不加品牌前缀。
7. 更新 `.codex/skills/README.md` 的索引。

## 验证与输出

- 检查 frontmatter，以及每个引用的文件和命令真实存在
- 用一次真实请求试触发，确认不会抢无关任务
- 汇报：触发场景、事实源、文件写集、验证方式、未覆盖边界
