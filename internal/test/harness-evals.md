## 目标形状

评测不追求一步做成真实模型的回放平台，先固定四件事：

1. **固定任务集入口。** 由一个机读的 manifest 持有任务清单。
2. **固定样本形状。** 每个 replay case 由四个文件组成：input（输入与运行上下文）、expected（期望结果）、grader（判定标准）、evidence-links（关联的证据位置）。
3. **固定摘要出口。** runner 统一产出 JSON 与 Markdown 摘要，之后的趋势报告从这里接。
4. **固定提升路径。** 真实失败由脚本从运行时目录提升为仓库内样本，并把绝对路径脱敏成占位路径。

## 三层样本来源

| 层次 | 作用 | 落点 |
| --- | --- | --- |
| 仓库固定样本 | 回归的稳定入口，不依赖本机会话 | internal/test/ 下的 manifest 所指位置（P6 建立） |
| 仓库沉淀样本 | 把值得长期回归的真实失败提升为资产 | 仓库根的 tests/fixtures/ 下 |
| 运行时自动发现 | 扫描本地会话目录并纳入统一摘要；允许零样本 | .lime-star/ 下 |
