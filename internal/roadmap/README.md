# internal/roadmap — 路线图

本目录是路线图事实源：按阶段写清产品往哪里走、按什么顺序做、每个阶段怎样验收。边界与目录归属以 `../aiprompts/architecture.md` 为准；本页只定义路线图层的用法。

## 与执行计划的分工

- 路线图回答做什么、按什么顺序、怎样算阶段完成，放本目录。
- 执行计划回答这一轮具体怎么改、改到哪了，放 `../exec-plans/`。路线图里每个阶段的开工话术都指向一个阶段计划。
- 路线图末尾的进度记录只追加阶段级结论（阶段、改动、验证、完成度、下一刀）。每一刀的写集与验证细节写在阶段计划里。

## 路线图文件的写法

- 开头写明本路线图满足的需求。需求文档放 `../prd/`，其中的需求条目用阶段标注由哪个阶段交付。
- 每个阶段固定七项：目标、退出条件、证据等级、lime 对照阅读、落地的规则与守卫、仓库所有者的验收动作、开工话术。
- 退出条件写可观察的事实，不写"做完了"。
- 对照 lime 时只写路径和要看的点，不复制原文。
- 每个阶段写明交付的需求编号和要读的需求文件；退出条件引用需求的编号，不复述需求。需求正文在 ../prd/。
