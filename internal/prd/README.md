# internal/prd — 需求

本目录是需求事实源：以用户目标写清产品要做什么、不做什么、怎样算满足。边界与目录归属以 `../aiprompts/architecture.md` 为准；本页只定义需求层的用法。

## 与其他层的分工

| 要回答的问题 | 去哪里 |
| --- | --- |
| 为什么做，有哪些可选方案 | `../research/README.md` |
| 做什么，不做什么，怎样算满足 | 本目录 |
| 按什么顺序做，每个阶段怎样验收 | `../roadmap/README.md` |
| 这一轮具体怎么改，改到哪了 | `../exec-plans/README.md` |
| 改代码时必须遵守什么 | `../aiprompts/README.md` |

## 写作要求

1. 以用户目标表达，不以内部模块表达：谁、在什么场景下、希望发生什么、怎样确认。
2. 每份需求开头写明状态（草稿或已确认）与确认人。未确认的需求不得被计划当成既定范围。
3. 只写做什么和为什么。实现步骤放执行计划，调查过程放研究。
4. 被替代且没有外部依赖的需求直接删除，历史归 Git。
5. 每条需求有编号，并标注承诺交付它的路线图阶段；路线图文件开头指向它满足的需求。
