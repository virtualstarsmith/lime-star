# 命令行：启动、配置与交互

摘要：`lime-star` 怎么安装启动、从哪里读配置、在终端上怎么输入输出。包含 R1、R4、R13。
先读：`../agent-practice.md`（术语、范围、全局约束）。相关：`turn.md` 的 R12（回合结束与取消）、`thread.md` 的 R9（`--resume`）。

## R1 安装与启动

### R1.1 输出版本号

陈述：`lime-star --version` 必须在标准输出打印一行 `lime-star <版本号>`，退出码为 0，不做别的事。

场景：
- R1.1-S1 给定命令已安装，当执行 `lime-star --version` 时，则标准输出只有这一行，退出码为 0。
- R1.1-S2 给定工作目录里没有模型配置，当执行 `lime-star --version` 时，则仍然成功，因为查版本不需要模型配置。

### R1.2 帮助

陈述：`lime-star --help` 必须列出全部参数及一句话说明。

场景：
- R1.2-S1 给定命令已安装，当执行 `lime-star --help` 时，则输出里有 `--version` 和一句话说明，退出码为 0。

### R1.3 未知参数

陈述：未知参数必须以退出码 2 结束，并把错误写到标准错误。

场景：
- R1.3-S1 给定命令已安装，当执行 `lime-star --nosuch` 时，则退出码为 2，标准错误指明未知的参数，标准输出为空。

边界：`--resume` 由路线图 P5 交付，在那之前帮助里不列它（R9.1）。

### R1.4 可安装

陈述：在干净克隆上执行 `uv sync` 之后，`uv run lime-star --version` 必须可用。

场景：
- R1.4-S1 给定没有安装过依赖的克隆，当执行 `uv sync` 并生成锁文件之后，则 `uv run lime-star --version` 满足 R1.1。

## R4 配置与密钥

### R4.1 模型配置来源

陈述：模型地址、密钥和模型名必须分别从环境变量 `LIME_STAR_BASE_URL`、`LIME_STAR_API_KEY`、`LIME_STAR_MODEL` 读取。

场景：
- R4.1-S1 给定三个变量都已设置，当启动会话并提交第一条消息时，则模型请求发往 `LIME_STAR_BASE_URL` 指定的地址，使用 `LIME_STAR_MODEL` 指定的模型。

决策 D-01：环境变量优先；缺项时才读工作目录下的 `.env`，并且只读这一个位置。备选是也读用户主目录，落选是因为配置来源多于一处时，用户无法确定哪个生效。

### R4.2 缺少配置时拒绝启动

陈述：模型配置缺任何一项时，启动会话必须失败：退出码为 2，并指明缺的是哪几个变量。

场景：
- R4.2-S1 给定缺少 `LIME_STAR_API_KEY`，当启动会话时，则不发起任何模型请求，退出码为 2，标准错误写出这个变量名。

### R4.3 密钥不泄漏

陈述：密钥不得出现在终端输出、请求日志、会话记录和证据包的任何位置。

场景：
- R4.3-S1 给定一轮包含模型请求和工具调用的会话，当它结束后，则请求日志、会话记录和终端输出里都搜不到密钥的值。
- R4.3-S2 给定模型接口返回了鉴权错误，当错误显示给用户时，则显示的内容不含密钥。

### R4.4 密钥样例文件

陈述：仓库必须提供 `.env.example`，只含变量名和占位值。

场景：
- R4.4-S1 给定仓库里的 `.env.example`，当打开它时，则每个变量都只有占位值，没有任何真实密钥。

### R4.5 密钥文件被忽略

陈述：工作目录里的 `.env` 必须被 Git 忽略。

场景：
- R4.5-S1 给定工作目录里存在 `.env`，当执行 `git check-ignore .env` 时，则它被报告为已忽略。

### R4.6 已跟踪文件里没有密钥

陈述：已跟踪的文件里不得出现常见格式的密钥。

场景：
- R4.6-S1 给定一个已跟踪的文件里写入了常见格式的密钥，当密钥检查脚本运行时，则它报错并非零退出。

决策 D-02：R4.4 到 R4.6 的守卫由路线图 P1 的密钥检查脚本承担，这三条只规定结果。备选是让产品命令在每次启动时自检仓库，落选是因为那是开发期的约束，不该由用户的每次启动承担。

## R13 终端交互

### R13.1 开始会话

陈述：不带参数执行 `lime-star` 必须在工作目录开始一个新会话：显示一行版本号和工作目录，然后等待输入。

场景：
- R13.1-S1 给定配置齐全，当执行 `lime-star` 时，则终端出现版本号和当前目录，随后出现输入提示。

决策 D-03：工作目录定义为启动 `lime-star` 时所在的目录，并且启动时显示。理由是路径边界和会话归属都以它为准。备选是用参数指定工作目录，落选是因为 MVP 的目录来源只该有一个。

### R13.2 提交回合

陈述：用户输入一行非空文字并回车，必须提交一个回合。

场景：
- R13.2-S1 给定会话正在等待输入，当用户提交一行文字时，则开始一个回合，这行文字成为会话记录里的用户消息。

### R13.3 空行

陈述：空行必须被忽略。

场景：
- R13.3-S1 给定会话正在等待输入，当用户只按回车时，则不开始回合，继续等待。

### R13.4 退出命令

陈述：`/exit` 必须结束会话，退出码为 0。

场景：
- R13.4-S1 给定会话正在等待输入，当用户输入 `/exit` 时，则进程以退出码 0 结束。

决策 D-04：`/exit` 是唯一的斜杠命令，其他以斜杠开头的输入当作普通消息。备选是对未知命令报错，落选是因为那要多一条分支，而 MVP 没有别的命令。

### R13.5 输出流向

陈述：正常输出必须写到标准输出，错误和警告必须写到标准错误。

场景：
- R13.5-S1 给定模型产出了一段文字，当它显示时，则它出现在标准输出里。
- R13.5-S2 给定模型调用失败，当错误显示时，则错误文本出现在标准错误里。

决策 D-05：界面文案用中文，给脚本识别的标记用 ASCII，例如批准提示末尾的 `[y/n]`。备选是英文界面，落选是因为验收环境和使用者都是中文；标记用 ASCII 是因为 Windows 控制台的代码页不稳定。

### R13.6 编码

陈述：输出必须是 UTF-8。

场景：
- R13.6-S1 给定输出里有中文，当输出被重定向到文件时，则文件是合法的 UTF-8，中文不乱码。

### R13.7 非终端输出

陈述：标准输出不是终端时，不得输出颜色和光标控制符。

场景：
- R13.7-S1 给定标准输出被重定向到文件，当回合结束后，则文件里没有转义序列。

### R13.8 丢弃回合中的输入

陈述：回合进行中收到的输入必须被丢弃，不得进入会话。

场景：
- R13.8-S1 给定回合进行中，当用户又输入了两行，则会话记录里没有这两行。

决策 D-06：丢弃而不缓冲。备选是把输入排到下一个回合，落选是因为冒烟脚本难以判断输入是否已被处理。

### R13.9 提示忽略了输入

陈述：回合进行中收到过输入时，回合结束后必须提示忽略了几行。

场景：
- R13.9-S1 给定回合进行中用户输入了两行，当回合结束时，则终端提示忽略了两行输入。

### R13.10 退出码

陈述：退出码必须只有三种：0 表示正常结束，1 表示进程无法继续的运行期错误，2 表示用法或配置错误。

场景：
- R13.10-S1 给定用户在输入提示处退出，当进程结束时，则退出码为 0。
- R13.10-S2 给定一个回合因模型出错而结束，当用户随后正常退出时，则退出码为 0，因为进程本身没有出错。

### R13.11 回合进行中的 Ctrl+C

陈述：回合进行中按 Ctrl+C 必须取消当前回合（R12.5），随后回到输入提示。

场景：
- R13.11-S1 给定回合正在进行，当用户按 Ctrl+C 时，则回合停止并显示已取消，随后回到输入提示。

### R13.12 输入提示处的 Ctrl+C

陈述：在输入提示处按 Ctrl+C 必须以退出码 0 结束会话。

场景：
- R13.12-S1 给定会话在等待输入，当用户按 Ctrl+C 时，则进程以退出码 0 结束。

### R13.13 输入提示处的输入结束

陈述：在输入提示处读到输入结束时，必须以退出码 0 退出。

场景：
- R13.13-S1 给定标准输入已关闭，当会话处在输入提示处时，则进程以退出码 0 结束。

边界：批准提示处的输入结束按拒绝处理（R7.9）。

### R13.14 显示模型文本与工具调用

陈述：回合进行中，终端必须显示模型产出的文本和每次工具调用的名称与目标。

场景：
- R13.14-S1 给定回合里调用了 read_file，当回合结束时，则终端上能看到这次调用的名称和文件路径。
- R13.14-S2 给定模型产出了一段文本，当这段文本产出后，则终端上显示它。

决策 D-07：不承诺逐字流式显示，一段文本产出后整体显示。备选是逐字显示，留到 MVP 之后评估。

### R13.15 显示结果摘要

陈述：每次工具调用的结果摘要应当可见。

场景：
- R13.15-S1 给定一次 read_file 调用完成，当结果显示时，则终端上有一行说明读到了多少行，或者出了什么错。

决策 D-08：结果摘要只占一行，写行数或错误类别，不回显完整内容。备选是回显完整输出，落选是因为它会刷屏，而完整内容已经在会话记录里。
