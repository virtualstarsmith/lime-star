# 工具：读写文件、执行命令与审批

摘要：Agent 能对项目目录做什么，哪些操作必须先经用户批准，路径边界管到哪里。包含 R5、R7、R8。
先读：`../agent-practice.md`。相关：`turn.md` 的 R12（工具出错不打断回合）、`thread.md` 的 R6（批准要写进会话记录）、`cli.md` 的 R13（输出规则）。

## R5 读取与浏览

### R5.1 读文件

陈述：read_file 必须读取工作目录内的 UTF-8 文本文件，返回带行号的文件内容。

场景：
- R5.1-S1 给定工作目录里有一个三行的文本文件，当 Agent 调用 read_file 时，则返回这三行，每行前面有行号。
- R5.1-S2 给定路径指向一个目录，当 Agent 调用 read_file 时，则返回"这是一个目录"的结果，不抛出异常。

### R5.2 行数上限

陈述：read_file 单次最多返回 2000 行；文件更长时必须说明总共多少行、还有多少行没读。

场景：
- R5.2-S1 给定文件有 5000 行，当 Agent 调用 read_file 时，则返回前 2000 行，并说明还有 3000 行没读。

决策 D-13：单次上限 2000 行。备选是按字节限制，落选是因为带行号的内容按行计，更容易被模型和用户核对。

### R5.3 二进制与非 UTF-8 文件

陈述：二进制文件和非 UTF-8 文件必须返回错误并说明原因，不返回内容。

场景：
- R5.3-S1 给定文件含有空字节，当 Agent 调用 read_file 时，则返回"二进制文件"的错误，不返回内容。
- R5.3-S2 给定文件是用 GBK 编码的中文文本，当 Agent 调用 read_file 时，则返回"非 UTF-8 编码"的错误，不返回内容。

### R5.4 列目录

陈述：list_dir 必须列出一个目录的直接子项，标明每一项是文件还是目录；路径为空时列出工作目录。

场景：
- R5.4-S1 给定工作目录里有两个文件和一个子目录，当 Agent 调用 list_dir 时，则返回这三项并标明类型。

决策 D-14：list_dir 不隐藏任何条目。备选是隐藏 `.git` 和 `.lime-star`，落选是因为隐藏规则会让用户和 Agent 看到不同的目录。

决策 D-27：MVP 加入只读的 list_dir。备选是不加，由用户报路径，或者每次批准一条列目录的命令，落选是因为那样 Agent 想知道目录里有什么就得批准一次。这条原来是未决问题，仓库所有者确认需求时没有另作答复，按推荐答案采用。

## R7 写文件、执行命令与审批

### R7.1 写文件

陈述：write_file 必须把给定内容原样写入工作目录内的路径，文件不存在时创建，存在时覆盖；不做换行符转换。

场景：
- R7.1-S1 给定目标文件不存在、它的父目录存在，当 write_file 被批准并执行后，则文件内容与提示中显示的内容逐字节相同。
- R7.1-S2 给定要写入的内容用 LF 换行，当写入后，则文件里的换行符仍然是 LF。

### R7.2 父目录不存在时失败

陈述：目标路径的父目录不存在时，write_file 必须返回错误，不创建目录，也不写文件。

场景：
- R7.2-S1 给定目标路径的父目录不存在，当 write_file 被调用时，则返回错误说明父目录不存在，磁盘上没有任何变化。

决策 D-15：不自动创建父目录。备选是自动创建并在提示里列出，落选是因为它让一次写操作同时改动了目录结构。

### R7.3 执行命令

陈述：run_command 必须在工作目录里执行给定的命令，返回退出码和输出；命令继承 lime-star 进程的环境变量。

场景：
- R7.3-S1 给定命令向标准输出打印一行文字并以 0 退出，当 run_command 被批准并执行后，则结果里有退出码 0 和这一行。
- R7.3-S2 给定命令以 1 退出并向标准错误打印信息，当执行后，则结果里有退出码 1 和这条错误信息。
- R7.3-S3 给定 lime-star 启动时的 PATH 里有 uv，当命令是 `uv --version` 时，则它能找到 uv。

决策 D-16：Windows 上命令由 PowerShell 解释，其他平台由 `/bin/sh` 解释。备选是 cmd，落选是因为它是更旧的控制台解释器，而验收环境的默认终端是 PowerShell。

### R7.4 命令超时

陈述：命令运行超过 120 秒时必须被终止，结果标明超时，并带上截至那时已有的输出。

场景：
- R7.4-S1 给定一条会一直运行的命令，当它运行到 120 秒时，则它和它的子进程都被终止，结果标明超时。

决策 D-17：超时固定 120 秒，MVP 不提供参数。备选是允许模型指定超时，落选是因为它扩大了工具面。

### R7.5 命令输出截断

陈述：命令输出超过 10000 个字符时，必须只保留最后 10000 个字符，并标明截掉了多少。

场景：
- R7.5-S1 给定命令打印了 30000 个字符，当执行后，则结果是最后的 10000 个字符，前面标明截掉了 20000 个。

决策 D-18：保留结尾而不是开头，因为报错信息通常在结尾。备选是保留开头，落选是因为 traceback 和编译错误的结论都在最后几行。

### R7.6 执行前必须批准

陈述：write_file 和 run_command 必须在得到用户批准之后才能执行：执行前出现批准提示并等待回应。

场景：
- R7.6-S1 给定 Agent 请求执行一条命令，当用户还没有回应时，则命令没有运行。
- R7.6-S2 给定 Agent 请求 read_file，当工具执行时，则不出现批准提示。

决策 D-19：危险与否按工具固定判定：write_file 和 run_command 是危险操作，read_file 和 list_dir 不是。备选是按参数判定，落选是因为那样规则不可预测。

### R7.7 写文件的批准提示

陈述：写文件的批准提示必须显示目标路径、是新建还是覆盖、全部要写入的内容。

场景：
- R7.7-S1 给定 Agent 请求写入一个三行文件，当提示出现时，则提示里能看到路径、新建字样和完整的这三行。
- R7.7-S2 给定目标文件已存在，当提示出现时，则提示标明会覆盖已有文件。

### R7.8 命令的批准提示

陈述：执行命令的批准提示必须显示原样的命令。

场景：
- R7.8-S1 给定 Agent 请求执行一条命令，当提示出现时，则提示里的命令与请求的逐字相同。

### R7.9 批准输入

陈述：批准提示的输入必须按下面的规则解释：只有 y 算批准，其他任何输入（包括空输入、n 和输入结束）都算拒绝。

场景：
- R7.9-S1 给定批准提示正在等待，当用户输入 y 时，则操作执行。
- R7.9-S2 给定批准提示正在等待，当用户直接回车时，则操作被拒绝。

决策 D-20：只认 y，空输入和看不懂的输入都算拒绝。备选是无效输入时重新提问，落选是因为情况不明时应当拒绝。

### R7.10 拒绝之后

陈述：被拒绝的操作必须不执行，并且必须记进会话记录（R7.12）。

场景：
- R7.10-S1 给定用户拒绝了写文件，当回合结束时，则目标文件没有被改动。
- R7.10-S2 给定用户拒绝了执行命令，当回合结束时，则这条命令没有运行过。

### R7.11 逐个批准

陈述：模型一次回复里请求了多个危险操作时，必须按顺序逐个批准；前一个被拒绝后，后一个仍然要提示。

场景：
- R7.11-S1 给定模型一次请求写两个文件，当回合进行时，则出现两次批准提示，各自独立决定。

决策 D-21：逐次批准，不做"本会话不再询问"。备选是会话级白名单，落选是因为安全边界会依赖会话状态。

### R7.12 记录批准

陈述：每次批准请求和用户的决定都必须写进会话记录，内容包括工具名、参数、决定和时间。

场景：
- R7.12-S1 给定用户拒绝了 run_command，当查看会话记录时，则有一条批准项，写着命令原文和拒绝。

### R7.13 拒绝后回合继续

陈述：用户拒绝一次危险操作后，回合必须继续：把"用户拒绝了这次操作"作为这次工具的结果交给模型。

场景：
- R7.13-S1 给定用户拒绝了写文件，当这次拒绝被记录后，则模型收到拒绝的结果，回合没有结束。

决策 D-28：拒绝后回合继续，用户想让它停就按 Ctrl+C。备选是拒绝即结束回合，更可预测，但用户只想否掉一种做法时必须重新发消息，所以落选。这条原来是未决问题，仓库所有者确认需求时没有另作答复，按推荐答案采用。

## R8 路径边界

### R8.1 只能访问工作目录

陈述：read_file、list_dir 和 write_file 的目标路径必须在工作目录内。

场景：
- R8.1-S1 给定 Agent 请求读取工作目录之内的一个文件，当工具被调用时，则允许读取。

### R8.2 越界时的处理

陈述：目标路径越界时，工具必须拒绝执行：不进入批准提示，不读写文件，并把"超出工作目录"作为工具结果交给模型。

场景：
- R8.2-S1 给定 Agent 请求读取工作目录之外的一个文件，当工具被调用时，则返回"超出工作目录"的结果，文件没有被读取。
- R8.2-S2 给定 Agent 请求写入工作目录之外的路径，当工具被调用时，则没有出现批准提示，返回越界结果，磁盘没有变化。

### R8.3 按真实位置判断

陈述：边界判断必须使用解析后的真实位置，包括展开 `..`、跟踪符号链接和目录联接；在 Windows 上比较时不区分大小写。

场景：
- R8.3-S1 给定工作目录里有一个指向外部目录的链接，当 Agent 通过它读取文件时，则被拒绝。
- R8.3-S2 给定路径先向上两级再回到目录内，当解析后仍落在工作目录内时，则允许访问。
- R8.3-S3 给定路径里目录名的大小写与实际不同，当在 Windows 上访问时，则按同一目录处理。

### R8.4 命令不受路径边界约束

陈述：run_command 不做路径检查，它的唯一安全边界是审批。批准提示因此必须显示原样命令（R7.8）。

场景：
- R8.4-S1 给定命令里出现了工作目录之外的路径，当 Agent 请求执行时，则仍然进入批准提示，由用户决定。

决策 D-22：路径边界只约束文件工具，不为命令做沙箱。备选是限制命令能访问的路径，落选是因为没有沙箱就做不到，而做沙箱超出 MVP。
