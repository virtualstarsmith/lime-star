# 回合：模型调用、循环与结束

摘要：一个回合怎么进行、有哪些结局，每次模型请求留下什么记录，Agent 必须怎样表现。包含 R2、R3、R12、R14。
先读：`../agent-practice.md`。相关：`cli.md` 的 R13（输入输出与 Ctrl+C）、`tools.md` 的 R7（审批）、`thread.md` 的 R6（会话记录）。

## R2 多轮对话

### R2.1 带上历史

陈述：每次模型请求必须带上当前会话到目前为止的全部历史，顺序与发生顺序一致。

场景：
- R2.1-S1 给定用户在第一轮说了一个名字，当第三轮问"我刚才说的名字是什么"时，则模型的回答里出现这个名字。
- R2.1-S2 给定上一个回合里有两次工具调用，当新回合发起第一次模型请求时，则请求里这两次调用和它们的结果都在，顺序不变。

### R2.2 行为约束一致

陈述：约束 Agent 行为的系统指令必须只有一个来源，同一会话的每次请求都带同一份。

场景：
- R2.2-S1 给定一个包含五个回合的会话，当检查这五次模型请求时，则系统指令逐字相同。

## R3 请求日志

### R3.1 每次请求一条记录

陈述：每次模型请求必须在请求日志里追加一条记录，包含时间、session_id、thread_id、turn_id、request_id、模型名、状态、耗时和 token 用量。

场景：
- R3.1-S1 给定一个回合里发生了三次模型请求，当回合结束时，则请求日志新增三条记录，request_id 互不相同。
- R3.1-S2 给定一次模型请求失败了，当它结束时，则请求日志里有一条状态为失败的记录。

决策 D-09：请求日志是一个 JSON Lines 文件，放在 `.lime-star/logs/` 下，每次请求追加一行。备选是按天或按会话分文件，落选是因为 MVP 的查询场景只是"找到这次运行的所有请求"。

### R3.2 不记内容

陈述：请求日志不得包含提示内容、回复内容和密钥。

场景：
- R3.2-S1 给定用户在消息里写了一段独特的文字，当请求日志写出后，则日志里搜不到这段文字。

### R3.3 失败只记类别

陈述：请求失败时，请求日志必须只记错误类别和接口状态码，不得记错误正文。

场景：
- R3.3-S1 给定模型接口返回了带请求详情的错误，当记录写出时，则只有类别和状态码，没有错误正文。

### R3.4 可关联

陈述：记录里的 thread_id 和 turn_id 必须与会话记录里对应项的标识相同，凭它们能找出一次请求所属的会话和回合。

场景：
- R3.4-S1 给定一条请求日志记录，当用它的 thread_id 和 turn_id 去查会话记录时，则恰好找到对应的那一个回合。

## R12 回合循环与结束

### R12.1 循环

陈述：一个回合必须按"模型请求、执行工具、结果写回会话记录、下一次模型请求"循环，直到模型给出的回复不再调用工具。

场景：
- R12.1-S1 给定模型的第一次回复调用了一次工具、第二次回复不含工具调用，当回合结束时，则会话记录里依次是工具调用、工具结果、最终回复。
- R12.1-S2 给定模型一次请求了三次工具调用，当执行它们时，则三次结果都写回会话记录之后才发起下一次模型请求。

### R12.2 工具结果不打断回合

陈述：工具出错、命令以非零退出码结束、操作被拒绝，都必须作为工具结果交给模型，回合继续。

场景：
- R12.2-S1 给定 read_file 读一个不存在的文件，当工具返回时，则模型收到"文件不存在"的结果，回合没有结束。

### R12.3 步数上限

陈述：一个回合最多发起 20 次模型请求。达到上限时回合必须结束，向用户说明原因，并且不再执行任何工具。

场景：
- R12.3-S1 给定模型每次回复都调用工具，当第 20 次请求结束时，则回合结束，终端说明已达到步数上限，会话记录的结局是步数上限。

决策 D-10：上限固定为 20，MVP 不可配置。备选是用环境变量覆盖，落选是因为它扩大了配置面，而 MVP 的任务用不到。

### R12.4 模型出错

陈述：模型请求失败时回合必须结束，向用户说明错误类别；MVP 不自动重试。

场景：
- R12.4-S1 给定模型接口返回鉴权错误，当请求失败时，则终端说明是鉴权问题，回合结束，会话记录的结局是出错，随后回到输入提示。
- R12.4-S2 给定会话历史超出了模型的上下文上限，当模型接口报错时，则按出错处理。

决策 D-11：不自动重试。备选是失败后重试两次，落选是因为它让冒烟和回放里的步数不确定。

### R12.5 取消回合

陈述：回合进行中按 Ctrl+C 必须取消这个回合：停止等待模型，终止正在运行的命令及其子进程，不执行后续的工具调用。

场景：
- R12.5-S1 给定一条命令正在运行，当用户按 Ctrl+C 时，则命令进程及其子进程都结束，终端显示已取消。
- R12.5-S2 给定回合在等待模型回复，当用户按 Ctrl+C 时，则不再发起任何请求，会话记录的结局是取消。

### R12.6 取消后会话可继续

陈述：回合被取消后，会话必须还能继续：lime-star 回到输入提示，下一条消息开始新的回合。

场景：
- R12.6-S1 给定一个回合刚被取消，当用户提交新消息时，则开始新的回合，并带上取消之前的历史。

### R12.7 记录结局

陈述：每种结局（完成、取消、出错、步数上限）都必须作为回合结局写进会话记录，并注明原因。

场景：
- R12.7-S1 给定一个被取消的回合，当查看会话记录时，则它的回合结局项写明取消。

## R14 Agent 行为约束

系统指令必须把下面四条写给模型。它们由模型执行，程序只能事后检查。

### R14.1 如实报告

陈述：Agent 在回复里对操作的说法必须与会话记录一致：说做过的操作在记录里有对应记录，没执行、被拒绝或失败的操作不说成已完成。

场景：
- R14.1-S1 给定一次写文件被用户拒绝，当 Agent 给出回复时，则回复里没有"已写入"的说法。

### R14.2 说明结果

陈述：回合的最终回复必须说明做了什么、结果如何，包括失败的命令和它们的退出码。

场景：
- R14.2-S1 给定回合里运行了一条以退出码 1 结束的命令，当 Agent 给出最终回复时，则回复指出这条命令失败了。

### R14.3 不绕过拒绝

陈述：被拒绝的操作，Agent 应当换一种用户能单独批准的做法，不得只为同一个目标换一个工具再试。

场景：
- R14.3-S1 给定写某个文件被拒绝，当 Agent 继续时，则它不再对同一路径发起写操作。

### R14.4 缺信息先问

陈述：任务缺少必要信息、工作目录里也找不到时，Agent 应当向用户提问，不得猜测。

场景：
- R14.4-S1 给定用户要求修改一个没有指明的文件，当目录里有多个候选时，则 Agent 先问是哪一个。

决策 D-12：R14.3 和 R14.4 是"应当"，不做硬门禁，由路线图 P6 的评测验证。备选是做成硬门禁，落选是因为模型行为无法由程序保证，硬门禁会让 MVP 的验收无法判定。
