# 证据：导出、回放与评测

摘要：怎么从会话记录导出证据包，怎么把一次真实失败变成仓库里的样本，评测怎么跑。包含 R10、R11。R11.1 由路线图 P3 交付，其余由 P6 交付。
先读：`../agent-practice.md`。相关：`thread.md` 的 R6（记录里要带关联键）。设计目标见 `../../tech/harness/README.md` 和 `../../test/harness-evals.md`。

## R10 证据导出

### R10.1 证据包

陈述：给定一份会话记录，必须能导出一个证据包，包含时间线、每次工具与命令的结果、警告，以及真实发生过的验证记录。

场景：
- R10.1-S1 给定一个包含写文件、运行脚本和一次拒绝的会话，当导出时，则证据包里有这三件事，顺序与记录一致。
- R10.1-S2 给定会话里没有运行过任何验证命令，当导出时，则证据包里没有验证记录这一部分，而不是一个空列表。

边界：先导出事实，再导出判断；解释性内容只能建立在导出的事实之上。

决策 D-25：证据包是一个目录，里面是一份逐事件的 JSON Lines 文件和一份可读摘要。备选是单个 JSON 文件，落选是因为摘要不适合放进 JSON。

### R10.2 可回溯

陈述：证据包里的每个条目都必须标明它来自会话记录的哪一项（会话标识加序号），两边的类型和内容必须一致。

场景：
- R10.2-S1 给定一个证据包，当逐条按标明的来源去查会话记录时，则每条都能找到，且内容一致。

### R10.3 警告

陈述：证据包必须把下面几类情况列为警告：被拒绝的操作、越界访问、被截断的输出、出错的工具或命令、被取消或中断的回合。

场景：
- R10.3-S1 给定会话里有一次越界读取，当导出时，则警告里有它，并指向对应的那一项。

## R11 回放与评测

### R11.1 请求夹具

陈述：真实的模型响应必须能录制一次并保存为夹具，之后测试默认用回放，不再调用真实接口。

场景：
- R11.1-S1 给定一个带工具调用的响应已录制，当回放驱动一个回合时，则不联网也能走完"请求工具、执行、回填、再请求、结束"。

边界：用回放取得的证据要标注"模型为回放夹具"，规则见 `../../aiprompts/quality-workflow.md` 第 1 节。

### R11.2 失败提升为样本

陈述：一次真实失败必须能由脚本提升为仓库内的回放样本，由四个文件组成：input、expected、grader、evidence-links。

场景：
- R11.2-S1 给定一次真实失败的运行，当提升脚本执行后，则仓库里出现这四个文件。

### R11.3 路径脱敏

陈述：提升样本时，必须把本机的绝对路径脱敏成占位路径。

场景：
- R11.3-S1 给定一次运行记录里含有本机的绝对路径，当提升脚本执行后，则四个文件里都搜不到这个路径。

### R11.4 评测

陈述：评测必须从一个机读的任务集清单读取样本，对每个样本给出判定，并输出 JSON 与 Markdown 两种摘要。

场景：
- R11.4-S1 给定清单里有一条固定样本，当评测运行后，则得到一份 JSON 和一份 Markdown 摘要，两者的结论一致。
- R11.4-S2 给定清单里没有样本，当评测运行后，则两种摘要都说明没有样本，退出码为 0。

### R11.5 只是派生物

陈述：证据导出、回放和评测只能消费会话记录及其派生物，不得成为第二份运行事实。

场景：
- R11.5-S1 给定一个回放样本，当它运行时，则它读取的是证据包或会话记录，不另外拼一份。

决策 D-26：派生关系固定为"会话记录到证据包，证据包到回放样本，回放样本到评测"，每一层只读上一层。备选是每一层各自读会话记录，落选是因为会拼出互不一致的摘要。

### R11.6 正式命令没有替身开关

陈述：正式命令不得提供回放或替身开关；回放夹具只在测试里使用。

场景：
- R11.6-S1 给定正式命令的全部参数，当检查时，则没有任何参数能让它用回放代替真实模型。
