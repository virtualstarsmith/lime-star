# 并行协作协议：窄写集与热区避让

## 1. 默认不启用

默认单 Agent 模式直接动手。只在以下条件之一成立时进入本协议：

- 仓库所有者明确说明有其他 Agent 在同一仓库工作；
- 工作树已有大量与本轮无关的脏改动；
- 任务要求登记到多 Agent 共享认领队列。

## 2. 启动协议

1. 先确认主线：读根 AGENTS.md 与当前执行计划，明确主目标；
2. 只读盘点：`git status --short -- <scope>`，**不要先改文件**；
3. 声明写集，三段式：
   - 我认领哪些（本轮要改的文件）；
   - 我只读哪些（要参考但不改）；
   - 我不碰哪些（明确避让）。

写集要窄：优先按垂直切片认领最少文件；不能用"整个 src/lime_star"替代真实写集。

## 3. 脏热区避让

- 目标文件已脏（非本 Agent 的改动）时不夹写，默认切到只读审阅；
- 必须改同一文件时，先汇报补丁点（文件、行区间、意图），等待合并窗口；
- 发现意外变化立即停下并上报，不要用 checkout、reset、stash 抹平；
- 共享热区先登记再动手，不夹写。本项目的共享热区：根 AGENTS.md、internal/aiprompts/architecture.md、scripts 根目录的全部脚本、governance 下的基线与契约清单、src/lime_star/protocol/、protocol/、internal/roadmap/agent-practice.md。

## 4. 执行计划避让

主计划文件出现并行分歧（如冲突标记）时，不在主计划中夹写；改写独立进度文件（命名见 `internal/exec-plans/README.md`），由主计划链接过来。进度记录只追加，不改写历史。

## 5. 收尾汇报

每刀收尾必须包含五项：

1. **认领写集**：实际改动的文件与范围；
2. **避让写集**：本轮避让了哪些热区；
3. **验证口径**：跑了什么命令、证据等级、未跑原因；
4. **下一刀归属**：主目标的下一阶段归谁、从哪里继续；
5. **治理分类**：current、compat、deprecated、dead 的增删变化，需要挂账的进 tech-debt-tracker。
