# 质量工作流：证据分级与最低验证

协议层级与目录边界以 `architecture.md` 为准。本页只回答一个问题：这一轮改动，最少要拿出什么证据才能宣布完成。

> 参考来源：lime 仓库 internal/aiprompts/quality-workflow.md 的证据分级与测试作者合同，按本项目语境改写。

## 1. 证据分级

| 等级 | 形式 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| Unit | pytest 单元测试，不联网 | 纯函数与状态机的确定性 | 跨模块接线 |
| Domain integration | 跨模块测试，模型外沿用替身 | 模块组装正确 | 回合入口契约、真实进程 |
| 入口集成 | 从 app 回合入口（start_turn 等）驱动 | 唯一边界的契约成立 | 真实终端的可见状态 |
| Current fixture | 用录制的 OpenAI 兼容响应驱动完整主链 | 主链接线正确 | 真实模型行为、真实终端 |
| Gate A | 读模型证据：thread 读取结果、transcript 快照 | 事实源的内容正确 | 真实进程链路 |
| Gate B | 真实 CLI 进程、真实输入、贯穿主链的可见输出；模型为真实接口或显式标注的回放夹具 | 端到端主链成立 | 模型输出的稳定性 |
| Live | 真实模型接口联测 | 所配置模型下能力成立 | 其他模型、长期稳定性 |

硬规则：

- Gate A 不能替代 Gate B；低级证据不得冒充高级证据，引用时写明等级。
- 用回放夹具取得的 Gate B 证据必须标注"模型为回放夹具"，不得写成真实模型通过。
- 生产路径不回退 mock；mock 只允许测试夹具明确使用。
- 测试从 public 入口进入（app 回合入口、CLI 命令），不直接调用私有函数伪造跨层成功。
- 等待业务事件，不用固定 sleep。
- 测试失败必须回写：修产品、修测试或补守卫，三选一，不允许跳过。

## 2. 改动类型 → 最低验证矩阵

| 改动类型 | 最低验证 | 附加门禁 |
| --- | --- | --- |
| 任意改动 | `npm run verify:local` | 无 |
| 文档与规则 | `node scripts/check-doc-links.mjs` | 无 |
| Python 源码与测试 | ruff check、ruff format 检查、mypy、pytest（路线图 P0 起由 verify:local 按路径触发） | 无 |
| 协议、契约、schema | 定向契约测试 | `npm run test:contracts` |
| 依赖声明 | `uv lock --check` | verify:local 全量 |
| 业务主链 | Current fixture 加 Gate B 冒烟（路线图 P4 起接入冒烟脚本） | 无 |

每行都必须绑定可执行命令；尚未接入的命令随路线图对应阶段补齐，补齐之前不得在收尾报告里写成已验证。

## 3. 验证记录纪律

- 每条命令记录：命令、结果、证据位置（日志、退出码、文件）。
- 未跑的命令必须写：未跑、原因、风险、后续触发条件。
- 完成度用百分比陈述；未验证部分不得写"完成"。
- 长任务在执行计划中维护验证矩阵的实时状态（模板：`../exec-plans/templates/task-plan.md`）。

## 4. 主链改动的验证合同

主链改动（业务主链、协议边界、持久化）开始前先在执行计划里填验证合同，模板：`../exec-plans/templates/agent-verification-contract.md`。普通改动默认低 token、定向验证，不默认跑全量。

## 5. 测试作者合同

1. 回合逻辑的变更优先写从 app 回合入口进入的集成测试；单元测试只守真正独立的纯函数和状态转移。
2. 测试必须从 public 入口进入，不直接调用私有函数伪造跨层成功。
3. 模型夹具必须提供结构化的固定响应；断言完整的请求、事件与 Thread、Turn、Item 对象，不只断言片段字符串。
4. 等待业务事件或终态条件，不用固定 sleep，也不靠长超时兜底。
5. 从构造参数注入路径、配置、时钟和模型客户端；测试不修改进程全局环境。
6. 每个测试使用隔离的临时目录；不依赖真实用户目录，也不依赖上一个测试留下的状态。
7. 不测静态常量；不为已删除的逻辑保留正向测试。
8. 失败信息必须包含场景、标识、期望值和实际值，不能只报超时。
