# internal/exec-plans — 执行计划

本目录存放会影响开发执行的版本化产物：执行计划、进度日志、阻塞记录、技术债追踪。

## 命名约定

- 专项计划：`<topic>-plan.md`
- 路线图阶段计划：`p<N>-<主题>-plan.md`，对应 `../roadmap/` 里路线图的同名阶段；路线图本身不放本目录
- 进度日志：`<topic>-progress.md`（并行避让或多刀拆分时使用）
- 常驻追踪：固定文件名 `tech-debt-tracker.md`

## 使用规则

1. 长任务（预计多轮、跨会话或影响主链）开始时新建计划文件；模板：`templates/task-plan.md`。
2. 计划不是一次性文档：推进状态变化时要同步更新；会改变实现顺序、范围或回滚策略的决策，必须记录在计划内或链接到这里。
3. 主链改动先填验证合同：`templates/agent-verification-contract.md`；普通开发默认低 token、定向验证，不默认跑全量。
4. 清理类工作不能直接回挂路线图的，登记到 `tech-debt-tracker.md`。
5. 被替代且无兼容负担的计划直接删除；仅在存在真实外部依赖或必须保留历史入口时，保留带退出条件的跳转说明。没有归档目录：历史归 Git，本目录只保留进行中的计划。
6. 提交遵守根 AGENTS.md 的提交规则：仓库所有者验收并明确说"提交"之后才 commit。

## 收尾要求

每个计划收尾必须输出（对应根 AGENTS.md 执行方式第 4 条）：

- 治理四分类：current、compat、deprecated、dead 各自新增或删除了什么；
- 验证结果与未验证原因；
- 完成度百分比；
- 来源声明；
- 下一刀（若主目标未完）。

进度记录纪律：每刀按日期追加，禁止改写历史记录；与并行进程冲突时不在主计划夹写，改写独立进度文件（见 `../aiprompts/parallel-agent-collaboration.md`）。
